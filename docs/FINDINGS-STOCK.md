# Разбор стоковой прошивки Orange Pi Zero 3 Android 12

Всё ниже проверено на файле
`~/Github/tmp/OrangePi_Zero3_Android12_v1.0/OrangePi_Zero3_Android12_v1.0.img`
(md5 `2fa5d4f1e890a03d7d8a36c410c8bd48`, сверен с `.md5sum`).

---

## 1. Формат образа

`IMAGEWTY`, 1 243 788 288 байт, 45 секций.

Заголовок (little endian):

| Смещение | Поле | Значение |
| --- | --- | --- |
| 0x00 | magic | `IMAGEWTY` |
| 0x08 | version | 0x0300 |
| 0x0C | subversion | **0x60** — совместимо с PhoenixCard |
| 0x18 | file_size | 1 243 788 288 |
| 0x20 | table_offset | 0x400 |
| 0x3C | count | 45 |
| 0x40 | entry_size | 0x400 (1024) |

Запись таблицы (1024 байта):

| Смещение | Поле |
| --- | --- |
| +0x08 | maintype, 8 байт |
| +0x10 | subtype, 16 байт |
| +0x24 | имя файла |
| +0x124 | размер секции, u32 |
| +0x134 | абсолютное смещение, u32 |

Данные начинаются с 0xB800.

**Важно:** таблица размеров, которая лежала в репозитории
(`scripts/unpack_imagewty.py`), неверна для этого образа: расхождение
97.8 МБ, размер `super.fex` занижен на 18 МБ. Скрипт заменён на
`tools/imagewty.py`, который читает таблицу из образа.

## 2. Ключевые секции

| Секция | Смещение | Размер |
| --- | --- | --- |
| `boot.fex` | 22 367 232 | 67 108 864 |
| `boot-resource.fex` | 16 357 376 | 5 876 736 |
| `vendor_boot.fex` | 89 477 120 | 33 554 432 |
| `super.fex` | 123 032 576 | 1 101 858 464 |
| `vbmeta.fex` | 1 241 670 656 | 8 192 |
| `dtbo.fex` | 1 241 690 112 | 2 097 152 |

`super.fex` — **Android sparse image** (magic 0xed26ff3a), 1.1 ГБ sparse,
3.0 ГБ raw (786 432 блока по 4096).

`boot.fex` — boot image v3, header 1580 байт, ядро 23 234 568 байт.
Ядро — **ARM64** (magic `ARMd` на 0x38, TEXT_OFFSET 524288).

## 3. Разделы внутри super

LP metadata v10.2, 3 слота по 65 536 байт, метаданные с 0x3000.
Таблицы начинаются после заголовка (256 байт), а не с его начала.
**Экстенты считаются в 512-байтных секторах**, не в 4096 — проверено по
ext4-магии на всех четырёх разделах.

| Раздел | Размер | Тип |
| --- | --- | --- |
| system_a | 833 998 848 (796 MiB) | ext4 |
| vendor_a | 110 854 144 (106 MiB) | ext4 |
| product_a | 161 099 776 (154 MiB) | ext4 |
| vendor_dlkm_a | 7 135 232 (6.8 MiB) | ext4 |
| system_b, vendor_b, product_b, vendor_dlkm_b | 0 | пустые (A/B без второй копии) |

Все разделы заняты на 100 % — свободного места внутри нет.

## 4. Раздел `super` на карте

`sys_partition.fex`: `super` = **6 291 456 секторов = 3 0 ГБ**.
Это ровно raw-размер super. Занято 1.06 ГБ → **внутри super свободно
~1.94 ГБ**, которые можно отдать под расширение разделов без изменения
таблицы разделов на карте.

## 5. Критично: userspace 32-битный

| Признак | Значение |
| --- | --- |
| `ro.system.product.cpu.abilist` | `armeabi-v7a,armeabi` |
| `ro.system.product.cpu.abilist64` | **пусто** |
| `/system/lib64` | нет |
| `/vendor/lib64` | нет |
| `app_process64` | нет |
| `app_process32` | ELF 32-bit ARM |

Ядро arm64, но Android-пользовательское пространство — только armv7.
Следствия:

- 64-битные приложения не запустятся вообще (Dolphin, AetherSX2/NetherSX2,
  свежие PPSSPP — под вопросом).
- Каждый процесс ограничен ~3 ГБ адресного пространства.
- Чтобы получить 64-бит, нужна пересборка AOSP с 64-битными
  `TARGET_SUPPORTS_64_BIT_APPS` — это уровень «полный AOSP».

## 6. Что уже есть в стоке

**GPU и медиа** (vendor):

- `libGLES_mali.so`, `lib/hw/vulkan.apollo.so` — вендорский Mali, ради
  которого и берётся Android;
- `libOmxVdec.so`, `libvdecoder.so` — аппаратное декодирование (cedarx);
- `audio.primary.apollo.so`;
- `android.hardware.tv.cec@1.0-impl.so` — управление по HDMI-CEC.

**Сборка:** Android 12 (SDK 31), `userdebug`, `test-keys`,
`ro.build.characteristics=homlet` (Android TV), device `apollo-p2`.

**Лончер:** `TvLauncher` (priv-app), плюс `TvdVideo`, `GalleryTV`,
`TvdFileManager`, `DragonAgingTV`.

**Google-сервисов нет** — сборка уже без GMS.

**Эмуляторов нет** — ни RetroArch, ни других.

**Раскладки геймпадов:** 186 файлов в `/system/usr/keylayout`:

| Бренд | Что есть | Чего не хватает |
| --- | --- | --- |
| PlayStation (054c) | DS4 (05c4, 09cc), DualSense (0ce6), 0ba0, 0268 + версии | — |
| Xbox (045e) | 028e, 02d1, 02dd, 02e0, 02e3, 02ea, 02fd, 0b12 и др. | — |
| Nintendo (057e) | только 2009 (Pro Controller) | Joy-Con (2006/2007), NSO-пады |
| 8BitDo (2dc8) | только 6101 | остальные модели (3106, 6001, 9020…) |
| Прочие | 0079, 044f, 046d, 000d и др. | — |

`idc` только для 054c 05c4/09cc, 0957, 248a — остальным падам idc не нужен.

## 7. Что из этого следует для пайплайна

1. **Сток менять можно и нужно через repack**, без AOSP: раскладки, APK,
   конфиги, debloat, `build.prop`.
2. **Разделы придётся расширять** (все 100 % заняты), но место внутри
   `super` уже есть — 1.94 ГБ. Значит нужен свой `lpmake`: пересобрать
   метаданные с новыми размерами и разложить данные.
3. **`super.fex` в IMAGEWTY имеет всего 352 байта запаса** до следующей
   секции. Если sparse-образ вырастет, надо переписать смещения всех
   последующих секций и `file_size` заголовка. Формат разобран, это
   делается нашими инструментами.
4. **AVB**: `vbmeta*` надо пересобрать с флагом «verification disabled»,
   иначе изменённые разделы не загрузятся.
5. **32-бит — главное ограничение.** Решение (принять или пересобирать
   AOSP) определяет весь набор эмуляторов.

## 8. Инструменты

| Файл | Назначение |
| --- | --- |
| `tools/imagewty.py` | разбор и правка IMAGEWTY (list/extract/replace) |
| `tools/sparse.py` | sparse → raw |
| `tools/lpunpack.py` | чтение LP-метаданных, извлечение разделов |

Написаны потому, что `imgRePacker` в репозитории нет, а `lpunpack` не
пакетируется ни в Fedora, ни в Debian.
